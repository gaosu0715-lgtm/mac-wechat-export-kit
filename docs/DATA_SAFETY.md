# 数据安全与威胁边界

项目没有远程上传、遥测、账号枚举、分库 glob 或后台监听；LLDB/debugserver 可能使用本机调试通信。完整 guide 只在本机交互同意后准备私有副本、仅重签主应用并限时调试取钥；已有密钥的 export 不做这些操作。工具不修改 SIP、TCC 或系统安全设置。此轮已编写代码、运行合成/模拟测试及另行授权的真实只读环境检查；没有启动/退出微信、真实取钥、真实签名或读取真实库/密钥，也没有触碰其他研究任务。

配置和密钥是当前用户拥有的 `0600` 常规文件，经 `O_NOFOLLOW` 打开并检查文件描述符。两库、父路径和已有 sidecar 拒绝符号链接。输出为新建 `0700` 目录和独占创建的 `0600` 文件，已有目录不覆盖。工具不修复源文件权限。

生产 SQLCipher 连接要求只读标志、`query_only=ON`、只读状态检查和 schema 读取验证。选择会话后在读取事务中检查计数、唯一 ID、顺序和参与者。没有明文全库副本；临时排序请求在内存中。SQLite 自身可能需要 WAL/SHM 协调，因此不承诺所有辅助文件零接触，也不阻止微信自身另行更新数据。

密钥不放在命令参数、标准输出、普通 session journal 或导出元数据里；两库完成 HMAC 与只读 schema 验证后才写本机 `0600` 的独立 `keys.json`。原生 SQLCipher 日志关闭，控制台错误仅使用固定代码。交互终端会显示用户需核对的本机路径和身份范围，但不显示密钥或聊天正文；这段本机确认界面本身也不应录制或公开。Python、LLDB、C 库与操作系统可能保留内存副本，不能保证密钥可擦除、不会进入 swap、崩溃转储或宿主记录。库摘要校验不验证作者身份，动态库本身必须可信。

运行时只新建本次 target，不 attach 现有进程；入口断点身份、进程 unique ID、PID 路径和当前用户均需核实。只有选定两库盐匹配后才能读有限参数。120 秒覆盖启动与等待，另有限制 PBKDF 次数、内存读取次数与总量；未知 stop、异常信号、所有权变动或取消立即停止采集。清理先删断点、脱离，再请人从本次副本菜单正常退出，只观察进程；工具不发送按路径/名称/标识解析的退出请求，不使用 Kill、killall 或强制结束。自动脱离失败的人工监督阶段不会再读内存或继续应用；提示中断或状态查询失败也不能在安全脱离前销毁 debugger 或恢复原版。

临时副本仍共享本人账号的容器与应用组，登录/同步可能写入原数据并被客户端感知。重签只限私有副本主应用，保留原版、嵌套厂商签名、沙盒与 Hardened Runtime。恢复核验失败会阻止导出，但不能保证崩溃、断电、关闭终端时自动恢复。源库只读与整个副本运行零写入是不同承诺。

HTML 对所有正文做转义、禁用脚本及外部资源。媒体正文不解码，XML 只输出白名单可读字段，不输出原始 XML、附件 token、下载地址或 AES 字段。这不等于一般隐私脱敏：正文、标题、引用显示名本身可能带姓名、地址、密码或链接，导出应始终视为私密数据。

路径与摘要检查不能防御有同一用户权限、能在检查后替换父目录或库的攻击者。不要在共享可写目录或有恶意本地进程的环境使用；不要把此工具当作安全沙箱。输出父目录应由使用者选择可信私有位置。

`.gitignore` 默认拒绝未知根文件，再排除数据库、密钥、导出、图片、日志、二进制和私有目录。但 Git 忽略规则不保护已经跟踪的文件，也挡不住 `git add -f`。发布前运行候选扫描，并人工检查 `git diff --cached` 与所有待发布文件；不要打包旧工作目录。

报告问题时只提供软件版本、固定错误码和最小合成复现。安全问题先在本机保留，不公开真实数据；项目尚未建立公开维护者联络渠道。
