# 真实验证的授权范围与剩余边界

先取得真实只读环境检查授权，随后所有者又明确同意下面第 1–6 项的一次 bootstrap-only 测试，并确认正常退出原版。实际完成一次副本签名/启动和两库认证；自动正常退出失败后，独立恢复确认副本已退出并禁用、原版完整性一致且运行中。用户已确认测试副本退出及原版正常。没有授权或运行第 7 项的新版真实导出，详细结果见 [验证记录](VALIDATION.md)。私有授权证据、配置、会话与密钥保留在仓库外，不随项目发布。

## 每次真实操作必须明确的范围

1. 用户在本机私有 setup 配置中精确选择本人当前用户目录下的一个账号 `db_storage`、目标会话昵称/备注、新的 `private-` 会话目录、原版应用和已审阅的库摘要；不把配置或密钥发到聊天里。
2. 先做环境与已选择账号路径的预检，不扫描账号或以元数据检查授权代替加密页读取授权。当前系统 Python 缺 Zstandard，完整导出 guide 会停止，但 bootstrap-only 不受这个无关依赖阻碍；本次已单独获准在项目 `.venv-release` 安装 Zstandard 0.25.0 并完成全部合成测试，但未核对该环境的真实 LLDB 链路；此安装授权不包含新的真实操作。
3. 如预检通过，再允许一个新会话内的实际操作：用户正常退出原版，复制原版到本次私有目录，只对副本主应用做一次 ad-hoc + Hardened Runtime 签名；准确执行 [15 项变更](BOOTSTRAP.md)，保留 application-groups、沙盒、其他原配置和嵌套厂商签名。不改原版、不深度重签、不关闭 SIP，不修改 TCC/系统安全设置。
4. 允许对 `contact/contact.db` 与 `message/message_0.db` 各读取 4096 字节加密页；仅启动一次本次副本，在最多 120 秒和既定参数读取上限内，观察匹配盐的 PBKDF 参数并验证逐库 raw key。用户在“已就绪”后手动进入自己的账号、完成手机确认；不操作其他账号。
5. 允许使用本次验证通过的 raw keys 对这两库执行只读 schema 验证，在本机 `0600` 文件保存；不打印、不上传、不把密钥放在命令行。页面变动、部分命中、超时或未知停止就终止，不再尝试。
6. 允许移除本次断点并脱离；当前修复版请用户核对本次副本并从其菜单正常退出，工具不再发送应用退出请求。只在确认无副本残留后注销本次副本注册并改回 `.disabled`；核验原版字节与签名不变后，通过原版精确路径按需启动。调试器脱离失败时保持终端与所有权，由用户正常退出；不强制结束。用户确认原版正常。
7. 若需要验证导出衔接，另行明确目标会话及是否可以新生成一次导出；用户确认工具只读解析出的唯一联系人/本人绑定后，仅读取该表，保存本地私有产物并验证摘要、计数与排序。此前已消费的导出不会默认重跑；如只授权验证前六项，应使用已测试的 `guide --bootstrap-only`，恢复确认后停止，不解析联系人或读取会话表，也不导出。

## 必须一并理解的风险

副本与原版共享应用组、容器和账号状态，副本登录/同步可能修改缓存、数据库或登录状态；授权范围不只是读一个联系人的正文。应用组还涉及进程通信。临时 ad-hoc 调试配置与 library validation 例外可能被客户端或安全产品感知，不能承诺无账号风险。密钥本身覆盖整个对应数据库，会话限制来自后续查询过滤。

自动清理不保证在权限弹窗、应用卡住、调试器 API 失败、宿主崩溃或断电时完成。取钥限时不等于人工恢复限时。工具不替用户批准系统权限；前提不足就停止，不为了继续而关闭 SIP、增加 unsigned-executable-memory 或修改系统安全设置。
